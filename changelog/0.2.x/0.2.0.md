# 0.2.0 — 2026-08-13

## Fixed

- **Unreported numeric observations** — METAR wind/temp/dewpoint/altimeter, TAF forecast wind, PIREP altitude/cloud base/top, and station elevation return `null` instead of a fabricated `0` when unreported; genuine zeros (calm wind, freezing temp, sea level) are unchanged. [#15](https://github.com/cyanheads/aviation-weather-mcp-server/issues/15)
- **Obscured-sky ceiling** — `aviation_get_metar` `ceiling_ft` now includes vertical-visibility-into-obscuration (`OVX`) layers instead of `null`/`Clear` under `LIFR`; new `ceiling_type` (`measured`/`indefinite`) and `present_weather` fields carry the ceiling's kind and the raw+decoded weather group. [#16](https://github.com/cyanheads/aviation-weather-mcp-server/issues/16)
- **Cloud-height datum** — `aviation_get_metar` `clouds[].base_ft`/`ceiling_ft` and `aviation_get_taf` `forecast_periods[].clouds[].base_ft` are now described in feet AGL, not MSL; the returned values were already correct, only the description was wrong. [#13](https://github.com/cyanheads/aviation-weather-mcp-server/issues/13)
- **`content[]` parity with `structuredContent`** — coordinates render at upstream's published precision (not a fixed 2/4 decimals), one-sided PIREP hazard bounds no longer vanish, and null/empty states (advisory altitude, severity, movement; TAF fields; station data types) render as explicit text instead of `SFC`/`UNL` or a dropped line. [#14](https://github.com/cyanheads/aviation-weather-mcp-server/issues/14)
- **PIREP schema text** — `turbulence`/`icing` no longer describe an empty array as a negative (`NEG`) report, and `clouds[].cover` now names its full code set (`SKC`, `CLR`, `VMC`, `IMC`) and flags that some values aren't cloud layers. [#24](https://github.com/cyanheads/aviation-weather-mcp-server/issues/24)
