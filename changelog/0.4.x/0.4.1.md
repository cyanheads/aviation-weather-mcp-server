# 0.4.1 — 2026-08-25

Framework and dependency maintenance. No tool, prompt, or handler in this server changed — every declared parameter, output field, and error contract is what 0.4.0 shipped.

## Added

- **`tests/tools/tool-input-contract.test.ts`** pins each tool's declared root parameter set and the root-strict / nested-strip split, so a parameter named in a doc but absent from a Zod schema fails here rather than in a caller.

## Changed

- **An argument key no tool schema declares is rejected by name instead of silently stripped.** The call comes back as a tool result with `isError: true` naming the key in `content[0].text` — not a JSON-RPC error code, and with no `structuredContent`. Previously the key was dropped and the call ran without it, so a caller sending `stationIds` got results for a missing `station_ids`. Strictness is root-level: an unknown key inside a nested `bbox` object is still stripped.
- **`.env.example` pins `MCP_SESSION_MODE=stateless`,** matching the Docker image, and a plain `GET /mcp` advertises `sessionMode: "stateless"`. With the variable unset the schema default `auto` resolves to `stateful`. No handler here asks the caller for more input mid-request, so nothing needs a session.
- **Bun pins move to `1.4.0`** — both `Dockerfile` stages and `packageManager`; `engines.bun` stays `>=1.3.0`. The build stage now carries `--platform=$BUILDPLATFORM` so each leg of the multi-arch image compiles natively.
- **Repo tooling follows the SDK rename** — `scripts/lint-packaging.ts` guards `node_modules/@modelcontextprotocol/server/dist/`, `scripts/lint-mcp.ts` drops the branch for the removed task-handler surface, and `devcheck.config.json` clears its `outdated` allowlist.
- **Vendored agent skills re-synced to the 0.12.3 set** — `add-tool` 2.20, `api-context` 2.1, `api-linter` 1.12, `api-telemetry` 1.7, and 16 others.
