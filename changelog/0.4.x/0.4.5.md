# 0.4.5 — 2026-09-09

## Added

- **`limit`** on `aviation_get_pireps` — bounds how many reports come back, applied after the observation-time sort, so a limited result is the most recent reports rather than an arbitrary slice. Disclosed via `limited`/`matched`, kept distinct from the existing `truncated`/`cap` upstream-cap disclosure. [#34](https://github.com/cyanheads/aviation-weather-mcp-server/issues/34)
- **`limit`** on `aviation_find_stations`' `bbox` and `state` modes — same disclosure shape as above. Rows are ordered by `icao_id` ascending, identifier-less stations (buoys, mesonet sites) last, so a limited draw is reproducible and leads with airports. Rejected alongside `station_ids`. [#36](https://github.com/cyanheads/aviation-weather-mcp-server/issues/36)

## Fixed

- **`aviation_find_stations`: a stray space in one `station_ids` entry no longer fails the whole call.** Identifiers are trimmed before the upstream query; only an empty or whitespace-only entry is rejected. An upstream rejection now raises a declared `upstream_rejected` reason with a mode-specific recovery hint instead of surfacing the upstream endpoint and response body to the caller. [#35](https://github.com/cyanheads/aviation-weather-mcp-server/issues/35)
- **`aviation_find_stations` no longer claims station IDs must be ICAO format.** A lookup matches the registry's own identifier — a 4-letter ICAO ID for an airport, other shapes for buoys and mesonet sites — so the description, field description, and `station_not_found` recovery hint now say that instead of the previous (inaccurate) ICAO-only claim. Unresolved-identifier guidance now splits on whether an id is IATA-shaped (the one diagnosable case) rather than on length. [#35](https://github.com/cyanheads/aviation-weather-mcp-server/issues/35)
