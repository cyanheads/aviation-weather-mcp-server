# 0.4.7 — 2026-09-19

## Changed

- **Tool error `content[]` text closes with `(reason <reason> · not retryable)`** whenever the thrown error's `data` carries a `reason` string or a `retryable` boolean — every declared rejection across the five tools (no stations/METARs/TAFs/PIREPs found, invalid bbox, and the rest). `structuredContent` is unchanged. [#458](https://github.com/cyanheads/mcp-ts-core/issues/458)
- **A malformed tool call's argument rejection carries `data.reason: "invalid_arguments"` and a `Recovery: <hint>` suffix in `content[0].text`** — a wrong type, unknown key, or missing required field now names the fix directly in the text a client displays. [#445](https://github.com/cyanheads/mcp-ts-core/issues/445)
- **An unrecognized or mis-cased argument key is corrected ahead of schema validation instead of rejected.** A call sending `stationIds` for `station_ids`, or an extra key a tool doesn't declare, now succeeds where it previously failed. [#452](https://github.com/cyanheads/mcp-ts-core/issues/452), [#453](https://github.com/cyanheads/mcp-ts-core/issues/453)
- **An out-of-schema argument rejects as `InvalidParams` (-32602)**, the code a client actually receives, rather than `ValidationError` (-32007). [#416](https://github.com/cyanheads/mcp-ts-core/issues/416)
- **A cancelled tool call always classifies `RequestCancelled` (-32011) and logs at `info`**, whatever the handler throws after its abort signal fires. [#421](https://github.com/cyanheads/mcp-ts-core/issues/421)
- **`src/index.ts` declares `sessionMode: 'stateless'` explicitly**, and the server card now publishes the resolved mode under the `_meta` key `io.github.cyanheads.mcp-ts-core/sessionMode`. [#376](https://github.com/cyanheads/mcp-ts-core/issues/376), [#387](https://github.com/cyanheads/mcp-ts-core/issues/387)
- **`no_stations_found`, `no_taf_available`, `no_pireps_found`, and `station_not_found` log at `notice` severity** instead of `error`, on both the Pino sink and the `notifications/message` a client receives — an empty search result is an ordinary answer, not an incident.
- **Bun engines floor raised to `>=1.4.0`.**
- **The skill tree moved from `skills/` to `framework-skills/`** — a server shipping `.claude-plugin/`/`.codex-plugin/` no longer hands its development skills to every installing agent. [#428](https://github.com/cyanheads/mcp-ts-core/issues/428)

## Fixed

- **The AWC fetch retry bounds each attempt on its own signal** rather than the shared request signal, so a retry-deadline expiry aborts the in-flight request instead of only between attempts.
