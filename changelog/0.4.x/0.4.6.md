# 0.4.6 — 2026-09-09

## Added

- **`departure_time`, `cruise_altitude`, `route_waypoints`** — optional args on `aviation_preflight_brief`. Each narrows one step: departure time selects the TAF forecast period the briefing reads against, cruise altitude bounds the PIREP search to a ±3,000 ft band, and route waypoints (semicolon-separated `lat,lon` pairs) become the `aviation_get_advisories` bbox widened by 1° per side. Omitting any still generates a brief, naming the assessment it could not make. [#22](https://github.com/cyanheads/aviation-weather-mcp-server/issues/22)
- **Station calls chunk to each tool's limit.** `aviation_get_metar` (10 stations) and `aviation_get_taf` (4 stations) instructions split across multiple calls once departure + destination + alternates exceeds the bound, instead of requesting an over-limit batch in one call. [#22](https://github.com/cyanheads/aviation-weather-mcp-server/issues/22)
- **Weather-risk summary replaces the Go/No-Go framing** — the synthesis step now asks for risk stated across the route plus explicit gaps and uncertainty, since the prompt carries no pilot, aircraft, or operational-minima context to justify a go/no-go call. [#22](https://github.com/cyanheads/aviation-weather-mcp-server/issues/22)

## Changed

- **`departure_icao`, `destination_icao`, and each `alternates` entry now require 4 uppercase letters.** Previously unconstrained (`departure_icao`/`destination_icao` were bare strings, `alternates` an unvalidated comma list) — a malformed identifier now fails schema validation before `generate()` runs, matching what `aviation_get_metar`/`aviation_get_taf` already enforce on the same values. [#22](https://github.com/cyanheads/aviation-weather-mcp-server/issues/22)
