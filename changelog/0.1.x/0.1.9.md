# 0.1.9 — 2026-08-13

## Changed

- **Supply-chain hardening** — `package.json` `overrides` pin `brace-expansion`, `fast-uri`, `ip-address`, `js-yaml`, and `postcss`; `js-yaml` ^3.15.1 alone clears 20 `bun audit` advisories.
- **`.mcpb` bundle stripping** — `scripts/clean-mcpb.ts` now also strips DuckDB's platform-specific native bindings, alongside the existing agent-doc strip, keeping bundles portable and under the registry's 25 MB cap.
- **Security contact** — vulnerability reports now route to `security@caseyjhand.com`.
- **Toolchain resync** — `skills/`, devcheck, and packaging scripts resynced to the `@cyanheads/mcp-ts-core` 0.11.5 set.

## Fixed

- **`aviation_get_pireps` PIREP lookback** — `fetchPireps` now sends `age=` to the AWC `/pirep` endpoint instead of `hours=`; that endpoint has no `hours` parameter and silently ignored it, so every value returned the same fixed window. [#17](https://github.com/cyanheads/aviation-weather-mcp-server/issues/17)
- **`aviation_get_pireps` conflicting/invalid filters** — `distance_nm` alongside `bbox` (where it has no upstream effect) now throws `conflicting_distance`; `altitude_min_ft > altitude_max_ft` now throws `invalid_altitude_range` instead of always returning `no_pireps_found`. `distance_nm` no longer defaults at the schema level, so an omitted value and an explicit 100 stay distinguishable. [#19](https://github.com/cyanheads/aviation-weather-mcp-server/issues/19)
- **`aviation_find_stations` state validation** — an unsupported `state` code now throws a typed `invalid_state` validation error instead of a misclassified `ServiceUnavailable`, and `DC` is now supported. `STATE_BBOXES` moves to a new `state-bboxes.ts` module alongside the `isSupportedState` predicate; `format()` no longer renders a dangling `**IDs:**` label for DC's identifier-less station. [#20](https://github.com/cyanheads/aviation-weather-mcp-server/issues/20)
